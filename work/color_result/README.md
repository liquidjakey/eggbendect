# COLOR 계란 검출 — 백엔드 인계 패키지

**COLOR(일반 촬영) 라인용 모델 3종입니다.** 속도·성능을 직접 재보고 고르실 수 있게
전부 넣었습니다. 아래 표를 보시고 `ai_server` 에 하나만 물리시면 됩니다.

> **아래 성적은 test 셋 최종 결과입니다** (4,854판 / 계란 46,060개).
> test 는 학습·튜닝 중 한 번도 열지 않고, 설정을 확정한 뒤 딱 한 번만 채점했습니다.
> 다만 **데이터 특성상 실제 라인 성능은 이보다 낮게 나옵니다** — 맨 아래 "실배포 주의" 반드시 읽어주세요.

## 어느 것을 쓸까

| | `yolo11n` | `yolo11m` | `rtdetr-l` |
|---|---|---|---|
| 파일 | `color_yolo11n.pt` | `color_yolo11m.pt` | `color_rtdetr-l.pt` |
| 크기 | **5.2 MB** | 38.6 MB | 63.2 MB |
| **CPU 속도** (8 vCPU) | **67 ms/판 · 14.9판/초** | 323 ms/판 · 3.1판/초 | 490 ms/판 · 2.0판/초 |
| GPU 속도 (A100) | **1.5 ms/판** | 3.1 ms/판 | 5.3 ms/판 |
| macro Recall | 0.884 | 0.898 | **0.900** |
| macro Precision | 0.884 | 0.903 | **0.905** |
| macro F1 | 0.883 | 0.900 | **0.901** |
| mAP50 | 0.944 | **0.956** | 0.954 |
| mAP50-95 | 0.943 | **0.955** | 0.949 |

**핵심: 세 모델의 성능 차이가 1.6%p 뿐인데 CPU 속도는 7.3배 차이납니다.**

- **라인 처리량이 빡빡하면 `yolo11n`** — macro Recall 1.4%p 내주고 속도 4.8배를 얻습니다
- **여유가 있으면 `yolo11m`** — mAP·정밀도 최상, 속도는 중간. **실배포 유력**
- **`rtdetr-l` 은 실사용 비추천** — macro 지표가 `yolo11m` 보다 0.002 높지만 CPU 에서 1.5배 느리고
  1.6배 무겁고 mAP50-95 는 오히려 낮습니다(0.949 vs 0.955). 모델 비교 기록용으로만 넣었습니다

> `ai_server` 는 현재 `device="cpu"` 로 돕니다(`app/model.py`). **CPU 속도 열을 보세요.**
> GPU 로 바꾸면 세 모델 다 실시간 처리가 되므로 그때는 `yolo11m` 을 쓰시면 됩니다.

## 사용법

추론 코드는 이 폴더에 복사하지 않고 **`src/core/color_infer.py` 한 곳에만** 둡니다.
(두 벌이 되면 한쪽만 고쳐서 어긋나기 때문입니다.)

```python
from ultralytics import YOLO          # rtdetr-l 은 from ultralytics import RTDETR
from color_infer import predict_flat

model  = YOLO("work/color_result/color_yolo11m.pt")
result = predict_flat(model, "tray_photo.jpg")
```

`ai_server` 에 물리실 때는 `app/config.py` 의 `AI_MODEL_PATH` 만 바꾸시면 됩니다.

### 클래스 번호

```
0 NORMAL           정상
1 CRACK            크랙      ← 식품안전 (살모넬라 침투 경로)
2 FOREIGN_MATERIAL 이물질    ← 위생 (깃털·분변)
3 DISCOLORATION    탈색
4 DEFORMED         외형이상
```

> ⚠️ **MONO 는 번호 체계가 다릅니다** (MONO 3번=혈반, COLOR 3번=이물질).
> `app/model.py` 가 `result.names`(모델이 들고 있는 이름)를 쓰는 방식이라 안전하지만,
> 클래스 이름을 코드에 직접 적으실 때는 주의하세요.

### 권장 추론 설정

```python
model.predict(source=img, conf=0.25, agnostic_nms=True, verbose=False)
```

**`agnostic_nms=True` 를 꼭 켜세요.** 안 켜면 같은 계란이 `FOREIGN_MATERIAL` 과
`DISCOLORATION` 으로 동시에 잡혀 한 칸에 계란 2개가 들어갑니다 (실측 중복 5.9% → 0%).

## ★ 실배포 주의 — 검증 성능과 실제 성능이 다릅니다

데이터셋의 **촬영 배치가 라벨과 거의 일치합니다.** 정상 계란은 9월 촬영분(960×853)에,
결함은 10월 촬영분(960×720)에 몰려 있고 **두 배치는 종횡비까지 다릅니다.**

그 결과 모델이 결함이 아니라 **"이 사진이 어느 배치인가"** 로 답하는 것을 학습했습니다.
`yolo11m` 을 배치별로 나눠 채점한 결과입니다.

| 클래스 | 202209 에서 | 202210 에서 | 격차 |
|---|---|---|---|
| **NORMAL** | **0.981** | **0.062** | −0.920 |
| CRACK | 0.612 | 0.938 | +0.326 |
| FOREIGN_MATERIAL | 0.611 | 0.993 | +0.382 |
| **DEFORMED** | **0.400** | 0.865 | +0.465 |
| DISCOLORATION | 0.910 | 0.889 | −0.021 ← 대조군 |

**같은 클래스인데 어느 배치 사진이냐에 따라 성능이 완전히 다릅니다.**
`NORMAL` 은 202210 배치에서 65개 중 4개만 찾았습니다 (test 기준).

`DISCOLORATION` 만 두 배치에 고르게 분포(2,656 / 2,459)하는데, **이 클래스만 격차가
없습니다.** 즉 "어떤 클래스는 원래 어렵다" 가 아니라 **배치 편향이 원인**이라는 증거입니다.

### 백엔드에서 알고 계셔야 할 점

- 실제 라인은 **카메라가 하나**라 종횡비가 고정입니다. 위 두 배치 중 한쪽처럼 동작합니다
- 만약 라인 카메라가 **960×720 계열**이면 **정상 계란을 거의 못 찾아 전부 불량으로 넘길 수 있습니다**
- 위 표의 macro Recall 0.898 은 **각 클래스가 자기 본거지 배치에서 채점돼 나온 부풀려진 값**입니다
- **연동 테스트 시 이상률이 비정상적으로 높게 나와도 백엔드 버그가 아닐 수 있습니다**

전처리로 없앨 수 있는 문제가 아닙니다(종횡비를 맞춰도 조명·배경·색조 차이가 남습니다).
데이터를 다시 모으는 것 말고는 해결책이 없어, **숨기지 않고 측정해서 드러내는 쪽**으로 갑니다.
